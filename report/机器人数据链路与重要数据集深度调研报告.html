先抽象机器人数据链路方法论，再用代表性论文和数据集说明这些链路如何实现、产出什么数据资产，以及公司如何搭建自己的数据闭环。

0. 结论先行

本报告调研范围：机器人 manipulation 数据链路（采集 → 同步 → 标准化 → 质检 → 融合 → 回流），以 8 个代表性论文/系统为主案例，覆盖国际（DROID、OXE、BridgeData V2、LIBERO、MimicGen）与国内（RH20T、AgiBot World、RoboMIND）路线；不涉及模型训练与部署细节，但会说明模型在数据链路搭建（扩增 / Real2Sim / 质检）中的作用边界。

结论 1：行业竞争焦点已从“采数规模”转向“链路能力”头部差异不在 raw trajectory 数量，而在 schema 统一、质检闭环、多源融合权重和失败回流机制。没有链路设计的数据集，规模越大清洗和复用成本越高。
结论 2：数据链路可抽象为 7 个环节，缺任何一环都会卡住规模化任务定义 → 采集协议 → 多模态同步 → 标准化 → 质量控制 → 融合扩增 → 失败回流。公司应先回答这 7 个问题，再决定采多少数据、买什么硬件。
结论 3：8 个主案例分别解决链路中的不同瓶颈
  • DROID — 分布式真机采集协议
  • OXE — 跨机器人标准化与 data mixture
  • RH20T — 多模态同步与接触丰富数据
  • BridgeData V2 — 低成本单臂快速起步
  • AgiBot World — 双臂/人形大规模真实任务
  • RoboMIND — 多 embodiment 统一协议 + 失败示范
  • LIBERO — 任务体系与 benchmark 设计
  • MimicGen — 仿真数据扩增与 subtask 复用
结论 4：多源融合与失败回流是成熟链路的两个“分水岭”跨机器人、真机、仿真数据不能简单 concat，必须带 source / embodiment / quality / task 权重；失败 rollout 应转为 failure taxonomy 和 targeted recollection，而非仅统计平均成功率。
结论 5：当前主流仍是“人采真机 + 工程化链路”，模型尚未替代 teleop8 个主案例中，DROID / RH20T / BridgeData / AgiBot / RoboMIND 的真机轨迹仍以 human teleop 为主；模型更多出现在 融合扩增（MimicGen：几何 + 仿真 subtask stitching）和 Real2Sim（SimFoundry：视觉重建 + 场景/asset 生成），而非端到端替代人工采轨迹。若目标是少采真机数据：结构化 manipulation 优先看 MimicGen，场景多样性优先看 SimFoundry；真机 action 轨迹本身，目前仍离不开 teleop。
结论 6：建议优先级 — 先建链路，再扩规模
  • Phase 1（立即）：统一 episode schema、action 表示、converter 模板 — 对标 OXE / LeRobot
  • Phase 2（短期）：单站 teleop 采集 + 回放 + 基础质检 — 对标 BridgeData V2 / DROID 协议
  • Phase 3（中期）：质量评分、版本管理、失败数据入库 — 对标 RoboMIND / AgiBot
不建议一开始追求 million-scale；schema 和质检未就绪时，数据越多技术债越重。

对公司启示：如果未来要多地点采集，必须先统一硬件/相机/标定/任务规范，否则后续清洗成本会指数上升。

  • 学习其采集协议和 metadata。
  • 多地点前先统一硬件基线。
  • 场景/任务要做分布监控。

数据画像

数据场景
多实验室桌面 manipulation，包含 pick/place/push/open/close 等常见技能。

RGB、state/proprio、action、language/task、robot embodiment metadata。

对公司启示：内部数据格式不要绑定单机器人，应从第一天保留 embodiment、action definition 和 source metadata。

技术链路

60 source datasets → per-dataset converter → RLDS episode schema → observation/action/language normalization → robotics data mixture → RT-1-X / RT-2-X training → cross-robot evaluation

亮点

  • 跨机器人数据标准化标杆。
  • 证明多源数据正迁移。
  • 开放了数据消费生态。

局限/坑

  • 源数据质量不均。
  • action adapter 难。
  • mixture 权重是隐性关键。

复用建议

  • 内部建立 converter 层。
  • 采用 dataset/source 权重。
  • 不要简单拼接数据。

机构/厂商：清华等。它回答“接触丰富任务中视觉、力、触觉、音频和动作如何同步记录”。
CoRL/RSS 2023110k+ sequences20TB

数据画像

数据场景
真实接触丰富 manipulation，多技能、多上下文、多机器人配置和多视角。
数据类型
RGB、depth、binocular IR、joint angle/torque、EEF pose、gripper、6DoF FT、audio、部分 fingertip tactile。
机器人
多种机械臂/夹爪/传感器配置。
数据产物
面向 one-shot imitation 和 multi-sensory manipulation 的真实序列。
模型参与
无 haptic teleop + 多传感器同步标定；价值在工程链路，不在生成式模型。

技术方法论

RH20T 的价值在于多传感器同步和标定，而不是只提供 RGB/action。接触任务往往需要力/触觉/音频等信号，纯视觉数据很难覆盖。

对公司启示：一旦要做接触丰富操作，数据链路必须提前设计传感器同步、标定和高吞吐存储。

技术链路

haptic teleoperation → robot + force/torque sensor + gripper → 8–10 global RGBD + in-hand cameras → audio + tactile + proprio/action → multi-sensor calibration → synchronized contact-rich sequences

亮点

  • 多模态最丰富。
  • 适合接触/力控/触觉研究。
  • 含 human demo video 和语言描述。

局限/坑

  • 标定和同步复杂。
  • 数据体量大，加载成本高。
  • 不同配置 schema 统一难。

复用建议

  • 先定义多模态 timestamp 标准。
  • 力/触觉单独版本化。
  • 建立传感器健康检查。

  • 55k/107k 等版本口径需区分。
  • digital twin 物理可信度需验证。

复用建议

  • 失败数据要单独入库。
  • 多机器人从统一协议开始。

  • 作为真机数据补充。
  • 先定义可验证 predicate。

9. 总结

本报告的核心判断是：机器人数据集是数据链路的产物，而不是起点。头部工作的价值不在于各自产出了多少 trajectories，而在于它们分别验证了链路中某一环节的可规模化做法。读完 8 个主案例和落地章节后，可以归纳出以下差异化洞察与行动方向。

关键洞察（来自横向对比）

洞察 1：标准化能力 > 同质规模 OXE 用 60 个异构源数据集 + RLDS converter 证明了跨机器人正迁移；RoboMIND 则用统一协议采集 4 种 embodiment。两者说明：converter 层和 metadata 设计是预训练数据的核心资产，而非单纯堆同构数据。
洞察 2：DROID vs BridgeData = 两种真机起步路径 DROID 走分布式、统一 Franka 栈、强调 in-the-wild 泛化；BridgeData V2 走低成本 WidowX、VR teleop、快速 RLDS 导出。早期团队应二选一：要泛化选 DROID 协议，要速度选 BridgeData 协议，不要混用 action 空间。
洞察 3：失败数据正在进入主流设计 RoboMIND 显式纳入 5k failure demos；AgiBot 引入 human-in-the-loop verification。行业趋势是从“只采成功 demo”转向成功 + 失败 + 质检评分的闭环数据资产。
洞察 4：仿真/扩增是补充，不是替代 LIBERO 和 MimicGen 解决了任务体系和长尾扩增，但 sim-real gap 客观存在。正确用法是：真机数据定 action 空间和成功标准，仿真数据补分布和长尾，两者通过 schema 和 version 绑定。
洞察 5：模型在数据链路里的真实位置 当前行业主流仍是 “人采真机 + 工程化链路”；模型尚未替代 teleop 成为真机轨迹主来源。模型更多出现在：扩增（MimicGen：少量 seed demo → 几何 + 仿真扩增）和 Real2Sim（SimFoundry：视频 → sim-ready 场景/asset）。若关心“模型能否帮我们少采数据”：结构化 manipulation 优先看 MimicGen，场景多样性优先看 SimFoundry；真机 action 轨迹仍建议以 teleop 为基线，模型生成数据作补充而非替代。

公司建设建议（收束第 5–7 章）

优先级建设项交付物对标
P0episode schema + action 规范 + converter 模板数据协议 v1、字段文档、转换脚本OXE / LeRobot
P1单站 teleop 采集 + 回放工具 + 入库质检首版数据集（100–500 条）、回放验证BridgeData V2 / DROID
P2质量评分 + 版本管理 + 分布监控quality dashboard、dataset registryAgiBot / RH20T
P3失败数据入库 + 多源 mixture + 仿真扩增failure taxonomy、mixture configRoboMIND / MimicGen

仍需跟踪的开放问题

  • Action 空间统一：joint position、EEF delta、dexterous hand 高维 action 之间尚无 industry-standard adapter，跨源训练仍需自定义映射层。
  • 版本与可得性：AgiBot Alpha/Beta/Colosseo、RoboMIND 55k/107k 等口径不一，引用和商用前需逐版本核实 license 与公开范围。
  • Real2Sim 可信度：SimFoundry / PolaRiS 等 Real2Sim 链路尚处研究阶段，physics metadata 和 sim-real 相关性仍需 case-by-case 验证，不宜作为早期唯一数据来源。

综上，公司建设机器人数据体系应从链路设计出发，而非从采数 KPI 出发。先把 schema、质检和 converter 跑通，再选对标路线扩规模；数据链路清楚，数据集才有长期复用和跨项目迁移的价值。
