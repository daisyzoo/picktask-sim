执行摘要

SimFoundry 是一套模块化 Real2Sim 研究系统（非商业 SaaS 平台），输入一段真实世界 RGB 视频， 自动输出可物理交互的仿真场景（Digital Twin）及其变体（Digital Cousins），用于机器人策略的仿真训练与真机策略的仿真评测。

定位澄清 SimFoundry ≠ 单一算法，≠ LeRobot 式数据平台，≠ 可直接 pip install 的产品。 它是将感知、资产生成、物理标注、场景增强、训评闭环编排在一起的工程流水线 + 研究方法论。

一、总体 Pipeline 架构

SimFoundry 将 Real2Sim 分解为三大主阶段（Extraction → Generation → Augmentation）， 并可选用背景重建分支融合 3D Gaussian Splat；最终导出至 PyBullet（物理稳定化）和 Isaac Lab（机器人训评）。

二、各阶段输入 / 处理 / 输出物

1 Extraction（提取阶段）

将原始 RGB 视频转化为逐物体的感知数据，为后续 mesh 生成与位姿对齐做准备。

维度内容
输入物
  • 原始 RGB 视频（默认取 frame 0 为代表帧）
  • 相机内参 K（由深度模型估计或已知标定）
  • （可选）立体图像对 → 使用 FoundationStereo
核心模型
Vim2depth DepthAnything3 Vsegimage SAM3 Vscene Gemini-Pro-3 Vinpaintdepth PriorDepthAnything
处理步骤
  1. 选代表帧 → 估计深度图 Ds → 升维为场景点云 Ps
  2. SAM3 提取地面 → 对齐仿真世界坐标系
  3. VLM 检测前景物体列表 {o₁…oₙ}
  4. 迭代分解：分割物体 → 提取 mask + RGB-D crop → 图像/深度 inpainting 移除该物体 → 重复直至无前景物体
输出物
  • 场景代表帧 Is、深度图 Ds、点云 Ps
  • 逐物体：分割 mask mi、RGB crop pirgb、深度 crop pidepth
  • 地面平面参数、仿真世界系对齐变换
  • （供背景分支）干净背景 RGB 帧序列（经视频 inpainting 后）
2 Generation（生成阶段）

从逐物体 crop 生成 sim-ready 3D 资产，标注物理属性，在 PyBullet 中完成穿透消除与稳定化，导出至下游仿真器。

维度内容
输入物 Extraction 阶段的逐物体 RGB crop、mask、深度；场景 RGB-D 与点云（用于位姿对齐）
核心模型
Vimage Gemini Image Vmesh Hunyuan2.1 / TRELLIS.2 Vpose FoundationPose Varticulation Gemini + Articulate Anything Vsegmesh P3-SAM CoACD 碰撞网格
处理步骤
  1. 图像增强 → 2D-to-3D 生成视觉 mesh ℳi
  2. 6-DoF 位姿估计与精化 → pi（位置+朝向+尺度）
  3. 关节物体：VLM 识别可动部件 → mesh 分割 → 生成 URDF 关节参数 → Critic VLM 迭代验证
  4. CoACD 生成碰撞几何；VLM 标注质量、摩擦系数等物理参数
  5. PyBullet 组装场景 → 逐步仿真消除穿透 → 缓存稳定位姿
  6. 导出至 Isaac Lab 等下游仿真器
输出物
  • 逐物体 视觉 mesh（.obj/.glb 等）+ 碰撞 mesh
  • 物体 6-DoF 位姿、尺度 si
  • 关节物体 URDF（revolute/prismatic 关节、质量、摩擦、阻尼）
  • 物理属性表：质量、摩擦、碰撞参数
  • Digital Twin 场景包：稳定化后的完整交互场景（前景物体）
  • 平均耗时：约 5 分钟/物体；可选 3 分钟/物体人工微调
3 Augmentation（增强阶段）— Digital Cousins

在 Digital Twin 基础上沿三个轴自动生成变体，用于扩增训练数据与测试泛化。

图 3 · Digital Cousins 三轴变体及下游数据生成

Cousin 类型 输入 处理 输出物
Object 孤立物体透明底图、原场景图、物体名称 VLM 功能部件分解 → 按几何/拓扑/外观三维度提议变体 → 图像编辑模型合成 → VLM 合理性过滤 → 重新走 2D→3D 变体物体 mesh + 元数据（部件、变体维度、prompt、验证结果）

Task 仿真场景截图、可交互物体列表、机器人约束 VLM 作为机器人专家提议 N 个可操作任务 → 编译为逻辑谓词目标条件 任务定义文件（目标状态、语义分组、demo 采集配置）

三、背景重建分支（可选）

前景物体由 mesh 表示；背景通过 3D Gaussian Splatting (3DGS) 实现高保真视觉。提供自动与手动两条路线，输出结构相同。

路线额外输入输出物优劣

五、技术栈关系：PyBullet · Isaac Sim · Isaac Lab

什么是 PyBullet？

PyBullet 是开源物理引擎 Bullet Physics 的 Python 接口， 用于刚体动力学仿真。在 SimFoundry 里它不是最终训练环境，而是 Generation 阶段的中间工具。

PyBullet 是什么

轻量级开源物理引擎，pip install pybullet 即可用，支持加载 URDF/OBJ mesh、碰撞检测、重力仿真。

在 SimFoundry 里干什么

把重建的物体 mesh 放进场景 → 检测并消除物体穿透 → 逐步仿真直到物体稳定落位 → 缓存最终位姿。

和 MuJoCo / Isaac 的区别

MuJoCo 是你们 pickcup 用的引擎；Isaac Sim 是 NVIDIA 重型仿真平台。PyBullet 更轻、启动快，适合场景质检与稳定化，训机器人仍导出到 Isaac Lab。

为什么不用直接在 PyBullet 里训机器人？ PyBullet 缺乏 GPU 大规模并行、光追相机、与 DROID/YAM 等现成机器人资产的深度集成。 SimFoundry 用它做「场景能不能用」的物理校验，正式训评交给 Isaac Lab。

七、局限性、工程门槛与落地建议

主要局限（论文自述）

  • 重度依赖 foundation models，继承各模型的失败模式（mesh 质量、尺度、遮挡）
  • 当前假设桌面/台面单平面布局，不支持多层或非平面场景
  • 自动背景 inpainting 在无纹理平面上可能产生幻觉
  • 3DGS 近场裁剪问题 → 部分实验使用 mesh 背景替代
  • 代码未公开，无法直接复现完整 pipeline

工程门槛拆解

维度要求对比 pickcup (MuJoCo)
硬件NVIDIA GPU（16GB+ VRAM），Linux 为主Mac CPU 可训 ACT
软件栈Isaac Sim + Isaac Lab + 10+ FM 服务MuJoCo + LeRobot
采集正面、少遮挡的单视频；手动路线需二次拍摄无需真机视频
调试重建错误难定位（感知链长）Scripted 逻辑透明
机器人需 DROID/YAM 等 Isaac 资产；换 G1 需自建 URDF已集成 Unitree G1
耗时~5 min/物体 + 可选 90 min 背景手工 XML 一次性
对本项目的建议 当前 pickcup 阶段（MuJoCo scripted IL + ACT）是合理轻量路径。SimFoundry 更适合「已有真机场景视频、需快速批量造相似仿真变体」的场景。 若需体验 Real2Sim，可优先尝试开源的 PolaRiS（评测向）或 SAGE（场景生成向）。
