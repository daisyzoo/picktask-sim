1. 模型概览与定位

2. 架构总览

最容易理解的方式是把它拆成三个独立模块： UMT5 负责读懂文字，5B DiT 负责在压缩后的潜空间里生成视频，VAE 负责像素与潜变量之间的编解码。 DiT 与 VAE Decoder 前后相接，但不是同一个网络。

2.1 一张图看懂：谁生成，谁解码

文本 prompt ──► UMT5 Encoder ──► 文本条件 tokens ──────────────┐ │ Cross-Attention 纯文本生成：高斯噪声 zT ───────────────────────────────────────────┤ ▼ 图生视频：首帧图像 ─► VAE Encoder ─► 图像 latent + mask ─► 5B Dense Video DiT │ 约 50 次 Flow Matching 迭代 预测 latent 速度场 vθ(zt,t,cond) │ ▼ 干净视频 latent z0 │ ▼ Wan2.2-VAE Decoder │ ▼ RGB 视频（121 帧）
直接回答疑问 1：视频 DiT 主干不是 Wan2.2-VAE Decoder。 DiT 是约 5B 参数的 Transformer 生成器，输入/输出都在 latent space； VAE Decoder 是卷积式解码器，只把最终 latent 放大还原为 RGB。 可以类比为：DiT 是“作画者”，VAE Decoder 是“解压缩器”。
模块输入输出职责是否负责生成内容
UMT5 Encoder 文字 最多 512 个文本 tokens 提供语义条件 否
Wan2.2-VAE Encoder RGB 图像/视频 48 通道时空 latent 训练时编码目标视频；I2V 时编码首帧条件 否
5B Video DiT 带噪 latent + 时间步 + 条件 latent 速度场/更新方向 多步把噪声变成结构化视频 latent 是，核心生成主干
Wan2.2-VAE Decoder 最终视频 latent RGB 帧 时空上采样和像素重建 否；不做扩散去噪

2.2 官方尺寸示例：121 帧 1280×704

RGB 视频： (T,H,W,C) = (121, 704, 1280, 3) VAE 4×16×16： (31, 44, 80, 48) 时间维：1 + (121-1)/4 = 31；首帧单独保留 DiT patch_size=(1,2,2)：(31, 22, 40) 个 tokens 序列长度 L： 31 × 22 × 40 = 27,280 每个 token 宽度： D = 3,072 Transformer： 30 层，24 heads，FFN dim=14,336

因此“VAE 压缩 4×16×16”与“总压缩 4×32×32”不是矛盾： 后者是在 VAE latent 上，DiT 自己又做了一次 (1,2,2) patchify。 官方所说的压缩率 64，指的是把像素标量数与 latent 标量数相比： (4×16×16×3) / 48 = 64。

2.3 训练与推理时，VAE Encoder 是否都参与？

  • 训练：VAE Encoder 把真实目标视频编码成干净 latent，给 Flow Matching 构造带噪训练样本。
  • T2V 推理：从高斯噪声直接开始，不需要编码目标视频；最终只调用 VAE Decoder。
  • I2V 推理：需要 VAE Encoder 编码输入首帧，再与 mask/带噪 latent 一起条件化 DiT；最后仍由 Decoder 输出视频。

2.4 Wan2.2-TI2V-5B 是世界模型吗？

重新评估：广义上可以视为生成式视频世界模型（generative video world model）， 更严谨的称呼是“具备世界建模能力的视频基础模型”。 动作条件不是 world model 的必要条件；历史观测、文本、相机轨迹或动作都可以是条件。 但官方没有把 TI2V-5B 命名为 world model，也没有充分证明它是可靠的通用物理模拟器。

世界模型层次要求TI2V-5B判断
生成式/观察型 学习世界观测的时空联合分布，生成可能的演化轨迹 学习 p(video | text, optional image)，能从文字生成世界轨迹或从首帧生成可能未来 符合
预测型 根据历史/当前观测预测后续状态 I2V 可作首帧条件续写；但整段 latent 由双向 DiT 联合生成，不是显式逐步状态转移 部分符合
交互式/可控型 根据动作或连续控制实时滚动环境 只有文本和可选首帧，不能像 Genie/游戏模拟器一样逐步接受操作 不符合
通用物理模拟器 稳定满足物体恒存、碰撞、因果和长程一致性，并通过专门评测 生成结果体现视觉时空先验，但官方主要报告画质/生成基准，没有证明可靠物理仿真 证据不足
为什么这次结论与上一版不同： 世界模型的学术定义本身存在“理解世界”与“预测未来”两种传统。近期综述明确把动作写成 optional，并将视频生成、自动驾驶、游戏和具身智能都列为世界模型路线。 因此，“没有机器人动作”不能作为否定依据。本文最终表述为： TI2V-5B 是广义生成式视频世界模型，但不是交互式世界模型，是否达到通用 world simulator 仍未被证明。

2.5 为什么 DiT 不直接在 RGB 像素上做 Flow Matching？

理论上可以，工程上代价极高，而且训练目标会被大量高频像素细节主导。 以 121×704×1280 为例：

表示张量/序列规模相对问题
原始 RGB 121×704×1280×3 = 327,106,560 scalars 直接预测每个像素的噪声/速度，显存与计算巨大
若 RGB 只 patch 2×2 27,258,880 tokens 全注意力不可行
VAE latent 48×31×44×80 = 5,237,760 scalars 约 62.5× 标量压缩（理想长视频边界趋近 64×）
DiT latent tokens 31×22×40 = 27,280 tokens 比 RGB 2×2 tokens 少约 1000×
  • 省算力：Transformer 不处理三亿像素标量，而处理两万多个 latent tokens。
  • 更偏语义：VAE 先吸收颜色、纹理、局部运动等冗余，DiT 更集中学习物体、布局和动态。
  • 把难题拆开：DiT 学“生成什么”，Decoder 学“怎样恢复清晰像素”。
  • 训练更稳定：latent 按通道 mean/std 标准化，尺度比原始复杂像素分布更适合高斯起点。
  • 代价：画质上限受 VAE 重建能力限制，过强压缩可能丢小文字、细纹理和快速运动。

2.6 VAE 接在后面，Flow Matching 如何训练？

阶段 A：先训练并冻结 VAE RGB video x ─► Encoder E ─► z_data = Normalize(μ) 阶段 B：训练 DiT（Decoder 不在每次训练前向里） ε ~ N(0,I) t ~ p(t) z_t = (1-t)·ε + t·z_data target velocity = z_data - ε v_pred = DiT(z_t, t, text/image condition) loss = ||v_pred - target velocity||² 阶段 C：推理 ε ─► Flow solver + DiT（40/50 次更新）─► ẑ_data ─► 反标准化 ─► VAE Decoder（只解码一次）─► RGB video

因而 VAE Decoder 不会干扰 Flow Matching：Flow 的整条轨迹都发生在 latent space， Decoder 只在终点执行一次。训练 DiT 时通常冻结 VAE，梯度不需要穿过 Decoder； Decoder 主要用于重建验证和最终输出。

2.7 “干净视频 latent”具体长什么样？

对官方 121 帧 720P 横屏配置，它是一个连续浮点张量 (B, C, T′, H′, W′) = (B,48,31,44,80)。 它不是缩略 RGB，也不能直接肉眼观看：

  • 每个 (t′,h′,w′) 位置是一个 48 维向量，混合编码局部外观、结构与运动信息。
  • 空间一个 latent cell 对应约 16×16 像素；时间上首位置对应首帧，后续每个位置推进约 4 帧。
  • 由于 3D 因果卷积有历史感受野，一个 latent 不只代表孤立的 4 帧块，还携带之前 chunk 的上下文。
  • DiT 再将相邻 2×2 latent cells 合成一个 token：原始 192 维（48×1×2×2）投影到 3072 维。
为什么并没有想象中难训： VAE 已先把视频压成连续、标准化的低维流形；Flow Matching 的监督不是要求 DiT 一步猜出 z_data，而是在随机位置 z_t 上学习近似直线的局部速度。 不过 VAE 若丢失关键信息，DiT 再强也无法从 Decoder 恢复，这就是 latent diffusion 的性能上限。

3. Wan2.2-VAE 与 3D Causal VAE 详解

VAE 是一个可训练的视频编解码器：Encoder 把昂贵的 RGB 视频压成小 latent， Decoder 把 latent 还原为视频；“3D”表示卷积同时看时间、高、宽， “Causal”表示时刻 t 的特征只能使用当前及过去帧，不能偷看未来。

3.1 为什么不是普通 2D VAE？

方案操作主要问题/收益
逐帧 2D VAE 每一帧独立压缩 简单，但相邻帧编码可能抖动，且无法压缩时间冗余
普通非因果 3D VAE 卷积同时查看过去和未来 离线重建好，但分块时边界依赖未来，不适合流式缓存
3D Causal VAE 只从时间轴左侧取上下文 兼顾时空压缩、时间一致性、首帧编码与 chunk-wise 推理

3.2 “Causal 3D Conv”到底做了什么？

对 kernel 为 3×3×3 的卷积，空间维左右对称 padding； 时间维不在未来侧补帧，而只在过去侧补 2 帧。可写成：

普通 3D 卷积： y[t] = f(x[t-1], x[t], x[t+1]) ← 看到了未来 x[t+1] 因果 3D 卷积： y[t] = f(x[t-2], x[t-1], x[t]) ← 只依赖过去与现在

官方 CausalConv3d 源码将 temporal padding 设为 (2×padding_t, 0)，即全部 pad 在时间左侧。 处理后续 chunk 时，这些“过去帧”不再用零填充，而从上一 chunk 的 feature cache 取回。

3.3 Wan2.2-VAE 的实际网络结构（官方源码）

RGB: (B,3,T,H,W) │ ├─ spatial patchify=2：每个 2×2 像素块搬到通道 │ (B,12,T,H/2,W/2) │ ▼ Encoder3d CausalConv3d 4 个尺度 stage，dim_mult=[1,2,4,4]，每级 2 个残差块 空间再下采样 2×2×2；时间标志 [False, True, True] → 总计 T/4 Middle: ResBlock → Attention → ResBlock Head: RMSNorm → SiLU → CausalConv3d │ ▼ 输出 μ, logσ²，各 48 channels │ 推理 encode() 使用归一化后的 μ ▼ latent: (B,48, 1+(T-1)/4, H/16, W/16) │ ▼ Decoder3d（镜像） CausalConv3d → Middle → 时空上采样 → 12 channels │ ▼ spatial unpatchify=2 RGB: (B,3,T,H,W)

3.4 为什么 RMSNorm 有助于保持因果？

关键不在名字，而在归一化所跨越的维度。若归一化统计量跨过时间轴， 第 t 帧的均值/方差会受未来帧影响，因果性就被破坏。Wan 的 RMSNorm 对每个 (t,h,w) 位置独立地沿 channel 维归一化，因此不会从未来时间位置读取统计量。 这也让同一层可以稳定复用历史 feature cache。

3.5 分块缓存（Feature Cache）如何工作？

输入采用 1 + 4k 帧结构。Encoder 先单独处理第 1 帧，之后每次处理 4 帧； Decoder 则每次处理一个 latent 时间位置。每一个 CausalConv3d 层都维护自己的历史缓存：

  • 普通 kernel=3 因果卷积：保存前 2 个 feature frames，供下一 chunk 左侧上下文使用。
  • 时间 stride=2 层：处理奇偶对齐并保存边界帧，使跨 chunk 的降采样结果等价于整段计算。
  • 首 chunk：没有历史，使用左侧零填充；后续 chunk 改用真实缓存。
chunk 0: [frame 0] → latent 0，缓存各层末尾特征 chunk 1: [frame 1..4] + cache → latent 1，更新 cache chunk 2: [frame 5..8] + cache → latent 2，更新 cache ... 因此峰值显存随“单个 chunk”而非完整视频长度增长

3.6 “VAE”中的 Variational 体现在哪里？

Encoder 最后输出两组 48 通道张量：均值 μ 与对数方差 logσ²。 训练时可通过重参数化 z = μ + σ·ε 采样并加入 KL 正则，使 latent 空间连续。 但官方 Wan2.2 推理包装器的 encode() 直接返回经 mean/std 标准化后的 μ，因此部署时表现得更像确定性视频 codec。

3.7 证据边界：不要把 Wan2.1 数字直接写成 Wan2.2

Wan 论文（arXiv:2503.20314）详细报告的是上一代 4×8×8、16 latent channels、127M 的 Wan-VAE，并给出三阶段训练、L1/KL/LPIPS/GAN 和 2.5× 解码效率结果。 Wan2.2 官方 README 明确确认的是新 VAE 的 4×16×16； 官方 vae2_2.py 进一步确认其 48 latent channels 与上述网络配置。 因此本文不再把“127M、2.5×”直接归因于 Wan2.2-VAE。

3.8 还有一个容易混淆的“因果”

VAE 是因果的，但 Video DiT 不是自回归因果 Transformer。 VAE 的因果卷积保证编解码可按时间块流式执行；DiT 在一次去噪步骤中仍对整段 latent 使用双向 self-attention。也就是说，“3D Causal VAE”不代表模型逐帧自回归生成。

4. 视频 Diffusion Transformer（DiT）

4.1 整体结构

主干为标准 DiT 变体，三阶段：Patchify → N × Transformer Block → Unpatchify。

模块实现细节
Patchify 3D 卷积 kernel (1, 2, 2)，stride 对应空间下采样 2×； 输出 shape (B, L, D)， 其中 L = [1+(T-1)/4] × (H/32) × (W/32)
Self-Attention 非因果全序列注意力；含 3D RoPE 位置编码（时间 + 高 + 宽维度）
Cross-Attention 嵌入 UMT5 文本条件（512 tokens），确保长上下文下指令遵循
FFN 标准两层线性 + 激活
时间步调制 共享 MLP（Linear + SiLU）处理 sinusoidal timestep embedding → 预测 6 个调制参数；MLP 跨所有 Block 共享，仅每层学习各自 bias。 该设计比每 block 独立 MLP 减少约 25% 参数。
Unpatchify 逆 patch 操作，还原为潜变量 shape

4.2 序列长度估算

以官方默认 121 帧、1280×704、24 fps（约 5 秒）为例：

VAE latent 网格： [1+(121-1)/4] × (704/16) × (1280/16) = 31 × 44 × 80 = 109,120 个 latent 位置（每位置 48 channels） DiT patchify 后： 31 × (704/32) × (1280/32) = 31 × 22 × 40 = 27,280 tokens（每 token 3072 维）

实际序列长度随分辨率和时长显著增大，注意力计算代价 O(L²)； 这是为何 5B 720P 单 GPU 推理耗时约 9 分钟的根本原因。

4.3 与 Wan2.2-A14B（MoE）的差异

主干类型 Dense 双专家 MoE（高噪专家 + 低噪专家）
总参数 5B 27B（每步激活 14B）

5. 文本编码器（UMT5）

Wan 系列统一采用 umt5-xxl（Google，多语言 T5 变体）作为文本编码器， 冻结参数，输出 512 tokens 的文本嵌入序列， 经 Cross-Attention 注入 DiT 每个 Transformer Block。

选择 UMT5 的依据（论文明确列出）：

  1. 强多语言能力：支持中文、英文及视觉文字理解。
  2. 组合理解优于同参数量 Unidirectional LLM。
  3. 收敛速度更快，同等算力下可达更低 loss。
在具身任务中的意义： UMT5 的中英双语能力使灵初 Psi-R2/W0 可直接以自然语言（含中文）作为任务指令条件， 无需额外翻译或重编码。

6. 训练流程与目标

6.1 生成范式：Flow Matching（Rectified Flow）

采用 Flow Matching 框架，在图像/视频潜变量域建模连续时间生成过程。 给定真实潜变量 x₁、高斯噪声 x₀ ~ N(0,I)、 时间步 t ∈ [0,1]（从 logit-normal 分布采样）， 中间状态：

xₜ = t·x₁ + (1−t)·x₀ （线性插值 = Rectified Flow） 真实速度场：vₜ = dx_t/dt = x₁ − x₀ 训练目标：MSE 速度预测 L = E_{x₀,x₁,t} ‖ u(xₜ, c_text, t; θ) − vₜ ‖² 其中 c_text 为 UMT5 嵌入（512 tokens）
关于 z₀ / z₁ 的记号： 不同 diffusion/flow 文献方向相反。上式令噪声为 x₀、干净数据为 x₁； Wan 官方推理代码却把求解器最终干净结果命名为 x0。 两者只是记号差异。本文在解释数据流时统一写 z_data（干净 VAE latent） 与 ε（高斯噪声），避免混淆。

相比 DDPM，Flow Matching 轨迹更直、步数更少； 同时与最大似然目标等价，理论基础完整。

6.2 多阶段预训练课程

阶段数据分辨率 / 帧数
①图像低分辨率预训练 大规模图像 256 px；建立语义-文本对齐与几何结构先验
②图像-视频联合第一阶段 256 px 图像 + 视频 视频：192 px / 5 秒 / 16 fps
③图像-视频联合第二阶段 提升分辨率 480 px；视频帧数不变
④图像-视频联合第三阶段 高质量数据 720 px / 5 秒视频

优化器：AdamW，weight decay=1e-3，初始 lr=1e-4，根据 FID / CLIP Score plateau 衰减。 训练精度：BF16 混合精度。

Wan2.2 相比 Wan2.1 训练数据量提升显著：图像 +65.6%，视频 +83.2%， 并增加了对光照、构图、色调、镜头运动等的精细标注。

6.3 I2V（图像→视频）融合训练

TI2V-5B 原生支持 I2V。官方推理代码先把单张参考图编码为首个 VAE latent， 再用 mask 将它写入完整的带噪视频 latent；每个采样步骤之后都会再次把已知区域钳回参考 latent， 以防首帧漂移。mask 还会展开成 per-token timestep：已知首帧与待生成区域使用不同的噪声时间信息。 这不是把 VAE Decoder 当作 DiT，也不是简单把图片 token 接到文本后面。

z_img = VAE.encode(reference_image) z = (1-mask) · z_img + mask · noise for each denoising step: velocity = DiT(z, expanded_timestep, text_context) z = solver_step(velocity, z) z = (1-mask) · z_img + mask · z # 重新固定首帧区域

7. 推理优化（缓存 / 量化 / 并行）

7.1 Diffusion Cache（步间缓存）

DiT 在多步去噪中，相邻步之间注意力输出高度相似；Classifier-Free Guidance（CFG）后期条件/无条件输出也高度相似。

  • Attention Cache：每隔若干步做一次注意力前向，其余步复用缓存结果。
  • CFG Cache：每隔若干步对无条件支路做前向，并加残差补偿防止细节退化（参考 FasterCache）。

对 Wan 14B T2V 模型，该策略提速约 1.62×，同等效果可应用于 5B 模型。

7.2 量化

  • FP8 GEMM：权重 per-tensor + 激活 per-token 量化，用于 DiT 所有线性层，相比 BF16 GEMM 约 2× 理论吞吐，实测 1.13× 模块加速。
  • 8-Bit FlashAttention（自研）： QK 用 Int8，PV 用 FP8 混合策略； 跨 block 用 FP32 累加防止长序列溢出； 实测 H20 上 MFU 95%，1.27× 推理加速。
注： TI2V-5B 官方 inference 脚本默认提供 --convert_model_dtype 选项将模型参数从 FP32 转换为 BF16， 以在 24 GB 显卡上可用；--offload_model True 和 --t5_cpu 可进一步减少峰值显存。

7.3 多 GPU 并行

  • FSDP（Fully Sharded Data Parallel）：对 DiT 参数切片，降低单 GPU 显存峰值。
  • Ulysses（Context Parallel）：在序列维度上切分，多 GPU 分担长序列注意力。
  • TI2V-5B 多卡示例：torchrun --nproc_per_node=8 ... --dit_fsdp --t5_fsdp --ulysses_size 8

8. 使用指南（快速开始）

8.1 安装

git clone https://github.com/Wan-Video/Wan2.2.git
cd Wan2.2
# 确保 torch >= 2.4.0
pip install -r requirements.txt

# 下载权重（约 10 GB）
pip install "huggingface_hub[cli]"
huggingface-cli download Wan-AI/Wan2.2-TI2V-5B --local-dir ./Wan2.2-TI2V-5B

8.2 文本→视频（T2V），单 GPU（RTX 4090）

python generate.py \
  --task ti2v-5B \
  --size 1280*704 \
  --ckpt_dir ./Wan2.2-TI2V-5B \
  --offload_model True \
  --convert_model_dtype \
  --t5_cpu \
  --prompt "两只猫穿着拳击手套在聚光灯下激烈对打"
注意： TI2V-5B 720P 分辨率为 1280×704（而非 1280×720）， 原因是 VAE 4×16×16 压缩要求高宽均须被 16 整除；704 = 44×16。

8.3 图像→视频（I2V），单 GPU

python generate.py \
  --task ti2v-5B \
  --size 1280*704 \
  --ckpt_dir ./Wan2.2-TI2V-5B \
  --offload_model True --convert_model_dtype --t5_cpu \
  --image examples/i2v_input.JPG \
  --prompt "夏日海滩，一只戴墨镜的白猫站在冲浪板上"

指定 --image 即切换为 I2V 模式；省略时为纯 T2V。

8.4 多 GPU 推理（8×GPU，FSDP + Ulysses）

torchrun --nproc_per_node=8 generate.py \
  --task ti2v-5B \
  --size 1280*704 \
  --ckpt_dir ./Wan2.2-TI2V-5B \
  --dit_fsdp --t5_fsdp --ulysses_size 8 \
  --image examples/i2v_input.JPG \
  --prompt "..."

8.5 Diffusers 接入

from diffusers import WanPipeline
import torch

pipe = WanPipeline.from_pretrained(
    "Wan-AI/Wan2.2-TI2V-5B-Diffusers",
    torch_dtype=torch.bfloat16
)
pipe.to("cuda")

video = pipe(
    prompt="一只猫在海浪里冲浪",
    num_inference_steps=20,
    height=704,
    width=1280,
    num_frames=81,     # ~5 秒 @24fps（实际约 5 s）
).frames[0]

8.6 提示词扩写（可选）

Wan 系训练时用丰富详细的 caption，简短 prompt 效果可能不及预期。 可通过 --use_prompt_extend + Dashscope API 或本地 Qwen 模型自动扩写： 

# 使用本地 Qwen 模型扩写
python generate.py --task ti2v-5B ... \
  --use_prompt_extend \
  --prompt_extend_method local_qwen \

10. 在具身智能中的应用（Psi-R2 / Psi-W0）

灵初以 Wan2.2-IT2V-5B-480P 为初始权重， 在约 10 万小时人类操作 + 真机数据上继续预训练，得到 Psi-R2 和 Psi-W0。 注意：这是在 Wan 视频生成骨干上新增动作接口后的模型； 它让广义视频世界模型进一步成为可用于控制的动作条件世界模型。

10.1 为何选择 Wan2.2 而非 LLM 骨干

维度视频 DiT 骨干（Wan2.2）LLM 骨干（如 OpenVLA）
时序建模 3D VAE + 时序 RoPE，原生适配视频序列 仅 2D patch token；时序需额外适配
视觉预训练规模 数十亿图像/视频，视觉细节丰富 以语言为主；视觉接入有限
生成/预测能力 原生支持文本/首帧条件视频生成；需加入动作条件并继续训练才成为控制意义上的世界模型 判别式；无法直接预测未来视频
场景泛化 预训练骨干已具备强跨背景泛化 需微调适配新视觉分布

10.2 具身微调的改动

  • Psi-R2：在 DiT 上新增动作预测头；训练目标从「预测视频速度场」改为「联合预测视频速度场 + 机器人动作序列」。
  • Psi-W0：将动作序列作为额外条件注入（类似图像条件的注入方式）；输出仍为条件视频预测。
  • 分辨率：灵初使用 480P 变体，降低显存压力，同时保证操作任务所需的空间细节。
  • 推理加速：DiT 缓存 + Torch Compile + 量化，将单步推理从 ~2.2 s 压到 <100 ms。

10.3 数据格式接口（SynData → Wan）

SynData 开源数据集已对齐 Wan 的输入格式： RGB 帧（head_rgb）+ 语言标注（caption）+ 手部关节角 qpos（映射为机器人动作）。 深度（head_depth）、触觉（glove_tactile）等模态作为附加条件输入， 真机无触觉时对触觉通道使用掩码（Mask Training）。
