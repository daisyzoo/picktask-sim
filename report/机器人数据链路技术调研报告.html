机器人数据链路技术调研报告

从数据采集、标准化、质量控制到多源融合与失败回流：对标 RoboNet、BridgeData V2、Open X-Embodiment、DROID、ALOHA、MimicGen、OpenVLA 与 Real2Sim 系统。

报告定位：技术链路调研 关注对象：机器人操作数据 输出日期：2026-07-08 关键词：采集 · Schema · 质检 · 融合 · 回流

0. 结论先行

本报告不讨论“数据为什么重要”，而是直接回答：行业头部如何把机器人数据从原始采集转化为可训练、可复用、可迭代的数据资产。

结论 1：链路比单点采集更关键 机器人数据价值不只来自轨迹数量，而来自任务定义、同步、质检、标准化、融合与失败回流是否贯通。
结论 2：跨机器人标准化已成主线 Open X-Embodiment 将 60 个数据集转成统一 RLDS，说明格式统一是跨 embodiment 学习的前置条件。
结论 3：真实场景多样性在提升权重 DROID 的价值不只是 76k 轨迹，而是 564 场景、86 任务、多采集者、多地点带来的真实分布覆盖。
结论 4：仿真与 Real2Sim 是补充链路 MimicGen、PolaRiS、SimFoundry 指向同一趋势：用可控生成补齐长尾，但不能简单替代真机数据。
结论 5：Action 表示决定数据复用边界 joint、EEF、delta pose、tokenized action、flow action 的选择，会影响跨机器人复用和后续模型路线。
结论 6：公司应优先建设数据底座 统一 schema、采集规范、自动质检、多源标记、版本管理和失败样本回流，应先于大规模模型路线选择。

2. 机器人数据链路总览

一条机器人数据从“任务意图”进入训练系统，要经历任务定义、采集、校验、标准化、融合、版本化和失败回流。模型训练只是数据消费端，不是本报告重点。

图 2：机器人数据链路闭环。回流不是模型失败后的附加动作，而是下一轮任务定义和补采的输入。
任务定义层定义 task / object / scene / skill taxonomy，使数据不是散乱 episode，而是可组合、可统计、可回流的样本。
采集层覆盖真机 teleop、scripted、仿真、人类视频和 Real2Sim，不同来源必须保留 source metadata。
标准化层统一 observation、action、timestamp、language、success、robot metadata，决定后续能否混合使用。
质量层做 schema、同步、动作、视觉、任务完成度和分布覆盖检查，防止低质数据污染训练集。

4. 数据标准化链路

机器人数据标准化的核心是把异构原始记录统一成可索引、可训练、可混合、可复现的 episode schema。

Episode { episode_id task: { task_id, language, success, success_predicate } observation: { images: { front, wrist, side, ... } depth / point_cloud state / proprio } action: { representation, vector, frequency, frame } timestamp: { camera_ts, state_ts, action_ts } metadata: { robot_id, embodiment, camera_config, calibration, scene_id, object_ids, operator_id, source, quality_score } }
标准化对象 常见问题 工程处理
时间同步 图像滞后 action、控制频率高于相机、丢帧、episode 边界不一致 resampling、nearest timestamp、interpolation、action delay compensation、fixed FPS export
Action 表示 joint / EEF / delta pose / gripper / tokenized action 互不兼容 记录 action space definition、坐标系、控制频率、单位、robot-specific adapter
Observation 表示 相机数量、视角、分辨率、深度质量、外参不同 camera naming convention、calibration metadata、view embedding、统一图像编码
任务语言 粒度不一致、同义表达、目标对象不明确 language canonicalization、task_id、object tags、success predicate 绑定
Robot metadata 不同 embodiment 的 DOF、夹爪、底盘、控制器不同 embodiment token、URDF/kinematic metadata、action head / adapter 映射

5. 数据质量链路

数据质量控制应前置到入库之前。对机器人任务而言，低质量 episode 不只是噪声，还可能教会模型错误接触、错误时机和错误恢复。

图 3：自动质检链路应覆盖字段、同步、动作、视觉、成功判定和分布覆盖。
完整性缺帧、缺 action、缺 metadata、episode 中断。
同步性camera/action/state timestamp 偏移，导致模型学到错误因果。
动作质量joint 越界、gripper 抖动、jerk 过大、控制器饱和。
任务质量成功/失败标注不一致，partial success 未区分。
视觉质量黑屏、过曝、遮挡、模糊、相机外参漂移。
分布质量任务、物体、场景、操作者集中度过高。

6. 多源数据融合链路

通用机器人数据不是简单 concat，而是带权重、带来源、带质量约束的 mixture。大数据集会淹没小而高质量的数据，仿真数据会改变动作分布，跨机器人数据会引入 action space 不一致。

P(sample) ∝ source_weight × task_weight × embodiment_weight × quality_score × long_tail_bonus
融合问题 具体表现 常用处理 代表项目
跨机器人 action 不一致 7DoF arm、6DoF arm、双臂、吸盘、夹爪动作维度不同 embodiment token、robot-specific action head、EEF frame abstraction OXE、RT-X、Octo、OpenVLA
数据集规模差异 大数据集主导训练，小数据集技能被稀释 temperature sampling、task-balanced sampling、source cap RT-X、Octo
真机/仿真混合 仿真量大但偏分布，真机少但物理真实 sim pretrain → real finetune、sim+real cotrain、failure-targeted sim augmentation MimicGen、SimFoundry、PolaRiS
语言粒度不一致 “pick up cup” vs “move object” vs 细粒度步骤描述 task canonicalization、language paraphrase、task_id 绑定 DROID、BridgeData V2、OpenVLA

7. 数据回流链路

机器人数据链路必须把失败变成下一轮数据输入。失败回流关注的不是模型指标，而是定位“缺哪类数据”。

图 4：失败样本回流链路。关键是给失败分类，而不是简单追加数据。
感知失败目标物体未识别、遮挡、光照变化、相机视角偏移。
抓取失败抓空、夹不稳、闭合时机错误、接触点偏移。
控制失败碰撞、动作抖动、关节限位、长时序 drift。
语义失败任务语言理解错误、目标对象歧义、顺序错误。

8.1 RoboNet: Large-Scale Multi-Robot Learning
定位：早期跨机器人经验共享数据集，关注多机器人视觉交互数据如何迁移到新平台。
CoRL 201915M+ frames7 robot platforms
15M+video frames
7robot platforms
113camera viewpoints
4–20×fine-tune data reduction claim

数据画像与适用边界

数据场景
桌面物体交互，包含 pushing、grasp-like interaction、object manipulation，重点是跨物体/视角/机器人泛化。
数据类型
RGB 视频帧、机器人动作、相机视角、机器人平台 metadata；语言标注弱。
适用机器人
Kuka、Sawyer、WidowX 等多种机械臂平台；适合分析跨平台视觉经验迁移。
如何使用
用于 video prediction 与 inverse model 预训练，再在 held-out robot 上少量 fine-tuning。

实现了什么

RoboNet 的核心不是把不同机器人动作空间完全统一，而是先把机器人-物体交互视频作为共享经验池，让视觉动力学模型学习“物体如何因机器人动作而变化”。

这条路线对现代 VLA 的启发是：跨机器人数据复用不一定从 action 对齐开始，也可以从视觉交互先验、场景变化和对象动力学开始。

技术链路图

亮点

  • 提出跨机器人共享经验库的早期工程范式。
  • 强调 camera viewpoint、robot platform、object 的多样性。
  • 证明 pretrain + 少量新机器人数据可优于纯新机器人数据。

局限 / 坑

  • 缺语言任务层，难直接服务现代 language-conditioned policy。
  • action space 统一弱，策略迁移不如视觉动力学迁移直接。
  • 主要是桌面交互，离复杂长时序任务较远。

数据画像与适用边界

数据场景
toy kitchen、tabletop、sink、stove、microwave、laundry 等 24 个环境，偏室内桌面操作。
数据类型
多视角 RGB/RGB-D、动作轨迹、自然语言 instruction；RLDS/TFDS 版本便于加载。
适用机器人
WidowX 250 6DoF 低成本机械臂，parallel gripper；适合低成本单臂平台参考。
如何使用
用于 goal-conditioned BC、language-conditioned BC、offline RL，也常被 Octo/RT-X 生态消费。

实现了什么

BridgeData V2 的技术价值在于把低成本机器人采集流程标准化：固定硬件平台 + VR teleop + 多环境 + 语言标注 + RLDS 格式，使数据能被不同下游算法复用。

它也展示了 teleop 与 scripted rollout 可以共存：teleop 提供真实人类策略分布，scripted rollout 补基础 pick-place 覆盖。

技术链路图

亮点

  • 低成本硬件 + VR teleop，工程复现门槛相对低。
  • 数据字段支持 language 与 goal image，消费方式灵活。
  • RLDS 兼容，能进入 OXE/Octo 类数据链路。

局限 / 坑

  • 单一 WidowX embodiment，跨机器人直接迁移有限。
  • 5Hz 控制不适合高动态或接触频繁的精细任务。
  • 场景虽多，但仍偏 toy kitchen 和桌面环境。
8.3 Open X-Embodiment / RT-X
定位：机器人数据标准化与跨 embodiment 数据混合的标杆，把异构历史数据转换为可共同训练的 RLDS 数据集。
2023/20241M+ trajectories22 embodiments
60source datasets
22robot embodiments
527skills

数据画像与适用边界

数据场景
多实验室机器人操作数据，主要是桌面 manipulation，覆盖 pick/place/push/open/close 等常见技能。
数据类型
RGB 图像、proprio/state、action、language/task、robot embodiment metadata；统一为 RLDS。
适用机器人
单臂、双臂、移动平台、四足等多 embodiment；但主体仍以机械臂操作为主。
如何使用
训练 RT-1-X、RT-2-X，也作为 Octo/OpenVLA 等开源策略的重要数据来源。

实现了什么

OXE 的硬核点在 converter 和 data mixture：每个源数据集要把自己的 observation、action、language、robot metadata 映射到统一 RLDS episode schema，再通过混合采样进入训练。

这证明“历史异构数据”不是废料，只要转换器和 metadata 足够完整，就能成为跨机器人预训练资产。

技术链路图

亮点

  • 从数据工程上定义跨机器人学习的统一接口。
  • 保留 embodiment 和 language，使模型能条件化到不同机器人/任务。
  • 证明数据多样性能带来正迁移，而不仅是单域过拟合。

局限 / 坑

  • 源数据质量不均，低质数据混入会影响 mixture。
  • 大多数仍是 tabletop/single-arm 数据，真实长尾不足。
  • action adapter 与采样权重是隐性关键，照搬 concat 不会得到同样效果。

RSS 202476k trajectories564 scenes

数据画像与适用边界

数据场景
家庭、办公室、实验室、厨房、卧室、走廊等真实 indoor scenes，强调 in-the-wild 分布。
数据类型
三路同步 RGB、depth、camera calibration、language annotations、Franka state/action。
适用机器人
Franka Panda 统一硬件栈；强在真实场景泛化，弱在跨 embodiment。
如何使用
用于训练或微调 robust manipulation policies，并作为真实场景泛化 benchmark。

实现了什么

DROID 的关键不是“采了 76k”，而是把分布式采集协议工程化：统一 robot setup、统一相机和标定、统一语言标注，使不同地点的数据仍能合并。

它把数据分布从实验台扩展到真实生活/办公环境，对公司自建数据链路最可借鉴的是硬件标准、calibration 入库和采集者协议。

技术链路图

亮点

  • 真实场景/建筑/操作者多样性强，覆盖实验室外分布。
  • 三视角、depth、calibration 同时入库，可复用性高。
  • 统一硬件栈降低分布式采集带来的系统性差异。

局限 / 坑

  • Franka 单 embodiment，跨机器人要另做 adapter。
  • 分布式采集需要严格协议，否则 label、calibration、operator bias 会变脏。
  • 长尾任务分布不均，训练时需要 task/source balancing。
8.5 ALOHA / ACT: 低成本双臂遥操作与 Action Chunk 数据
定位：高质量双臂精细操作数据链路，关键在主从遥操作、多相机同步、高频连续动作和夹爪接触时机。
2023Bimanual teleopAction chunking
双臂leader-follower teleop
多相机外部 + wrist views
连续动作joint/gripper stream
ACTchunk-level action data

数据画像与适用边界

数据场景
双臂桌面精细操作，如插拔、抓取、整理、折叠、开合、厨房类操作；强调接触和时序。
数据类型
多相机 RGB、双臂 joint state、双夹爪状态、连续 action sequence；通常是高质量成功示教。
适用机器人
ALOHA 低成本双臂、Mobile ALOHA 移动双臂；可迁移到类似主从遥操作双臂平台。
如何使用
作为 imitation learning 数据，ACT 一次预测 action chunk，Diffusion/BC 也可消费类似时序数据。

实现了什么

ALOHA/ACT 的数据链路把“人类手上操作”映射成机器人双臂同步动作流。这里的硬核点不是轨迹数量，而是轨迹质量：多视角、连续动作、夹爪闭合时机和接触阶段都必须同步准确。

ACT 的 action chunk 把单帧监督变成一段未来动作监督，提升长时序动作平滑性，但也反向要求图像、proprio 和 action 的时间对齐非常干净。

技术链路图

亮点

  • 低成本双臂硬件也能采高质量精细操作数据。
  • 多相机 + joint/gripper 同步，适合接触丰富任务。
  • action chunk 让示教数据表达未来短时动作计划。

局限 / 坑

  • 对硬件形态依赖强，跨 embodiment 复用要重做 action adapter。
  • 时间同步误差会被 chunk policy 放大，导致闭环接触失败。
  • 人工遥操作成本仍高，复杂任务需要大量高质量成功示教。

数据画像与适用边界

数据场景
仿真机械臂 manipulation，适合 pick-place、assembly、object rearrangement 等结构化任务。
数据类型
source demos、object poses、subtask boundaries、state/action trajectories、success predicates。
适用机器人
主要依赖 RoboSuite 等仿真机械臂环境；适合有 oracle state 和可重放控制器的机器人任务。
如何使用
用少量真实/人工 seed demos 生成大量仿真 demos，再用于 BC 或其他离线策略训练。

实现了什么

MimicGen 的关键思想是 object-centric subtask reuse：把示教分成接近、抓取、移动、释放等子任务，再根据新物体位姿做轨迹变换和拼接。

它适合“结构清楚、目标可由物体位姿定义”的任务；对于柔性物体、复杂接触和强动力学任务，自动拼接质量会下降。

技术链路图

亮点

  • 把少量高质量示教扩展为大量可训练仿真轨迹。
  • 子任务级复用比整条轨迹复制更能覆盖位姿变化。
  • 自动 success predicate 可用于大规模过滤失败生成。

局限 / 坑

  • 依赖仿真和 privileged state，真机直接复用难。
  • 任务必须可分解且几何结构稳定。
  • 生成数据仍可能有 sim-real gap，需要真机数据校准。
8.7 Octo / OpenVLA: 通用策略对数据链路的反向约束

实现了什么

Octo/OpenVLA 的意义在于反向定义了公司数据应保留哪些字段：不仅要有图像和动作，还要有高质量语言、robot embodiment、相机视角、action representation。

如果数据只记录裸 action 和图像，后续很难接入 VLA 或通用策略生态；如果保留完整 metadata，就能更低成本 fine-tune 或做 cross-model benchmark。

亮点

  • 开源生态降低通用策略微调门槛。
  • 把语言字段、embodiment metadata 和 action schema 提升为一等数据字段。
  • 适合作为公司数据格式兼容性的反向验收标准。

局限 / 坑

  • 泛化不是无条件成立，未覆盖 embodiment 仍需大量适配数据。
  • action token/continuous head 对精度、频率和归一化非常敏感。
  • 推理频率和真实控制器延迟可能成为落地瓶颈。

数据画像与适用边界

数据场景
真实桌面/室内操作场景，通过视频或扫描恢复为仿真场景；SimFoundry 偏 digital twin + cousins。
数据类型
RGB video、segmentation mask、depth/point cloud、mesh、3DGS、object pose、physics metadata、sim scene。
适用机器人
取决于下游 simulator 和 robot assets；论文中常见 DROID/YAM/Isaac Lab 生态。
如何使用
用于 sim-based policy evaluation、sim data generation、object/scene/task variation。

实现了什么

Real2Sim 的硬核点不是“重建好看”，而是把真实场景转成 physics-ready：物体 mesh、碰撞体、位姿、质量、摩擦、稳定化后才能进入机器人数据链路。

SimFoundry 进一步把重建场景扩展为 digital cousins：保留 affordance，同时变化物体、布局和任务，形成数据扩增链路。

技术链路图

亮点

  • 把真实场景引入仿真链路，可用于真实分布下的仿真评估。
  • digital cousins 能系统扩展 object、scene、task 维度。
  • 可为长尾场景和高风险真机测试提供补充数据。

局限 / 坑

  • 链路长，依赖 segmentation、depth、2D-to-3D、VLM、physics 多模块。
  • 物理参数近似会影响 contact-rich manipulation 可信度。
  • 工程门槛高，短期更适合作补充而非主采集链路。

9. 对公司机器人数据体系的启示

1. 先统一数据 schema Episode、task、observation、action、timestamp、metadata、success、quality_score 必须有稳定定义。
2. 采集规范先于模型扩张 任务模板、起止标准、成功标准、相机命名、action space 定义应先固定。
3. 自动质检前置 每条数据入库前做 schema、timestamp、video、action、success、distribution 检查。
4. 保留 source 与 embodiment 标记 未来数据会来自真机、仿真、开源集、Real2Sim、人类视频，必须从第一天可追踪来源。
5. 数据 mixture 要可配置 按任务、场景、机器人、质量、来源和长尾程度采样，避免简单拼接。
6. 建立失败样本回流 失败 episode 应进入 failure taxonomy，驱动定向补采或仿真增强。

10. 总结

机器人数据链路的核心，不是单次采集多少数据，而是能否把任务定义、采集、标准化、质检、多源融合和失败回流串成稳定闭环。

从 RoboNet 到 Open X-Embodiment，再到 DROID、MimicGen 和 SimFoundry，行业趋势已经很清晰：机器人数据正在从单机器人、单任务、单场景，走向跨机器人、多场景、多来源的标准化数据链路。

公司如果要长期建设机器人能力，应优先完成统一数据 schema、采集规范、质检系统、多源融合策略和失败样本回流机制。这些能力比短期选择某一个模型算法更底层，也更长期。
